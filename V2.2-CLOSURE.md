# 2.2.0-rc.0 local closure

Date: 2026-11-06 (Europe/Madrid). Branch: `feat/2.2-small-operators`.
Package and lockfile agree on `2.2.0-rc.0`. This closes the local preparation
scope of POST-2.1-PLAN.md; it does not claim a published package or remote CI run.

## Delivered scope

Both runtime waves are implemented and verified:

- Functional `semaphore({ permits, key?, maxQueue? })`, with FIFO admission,
  partitioned pools, queue overflow, cancellation withdrawal and ownership until
  inner settlement. `@Semaphore` uses the same operator and PermitQueue while
  retaining per-instance state and synchronous execution start.
- Opt-in weak receiver partitions for memoize/cachedFor, bounded FIFO cachedFor
  including pending entries, lazy expiry pruning and replacement-safe rejection
  cleanup. Handles retain invalidate/clear and exclude perReceiver.
- CircuitBreaker `isFailure(error, info)` across operators, decorators and
  definePolicy, with ignored errors, generation checks and cancellation priority.
- Retry maxDelayMs and none/full/equal jitter, applied after exponential backoff
  and both delay caps. Optional describe fields preserve existing defaults.
- Named-interface Observer event maps and explicit invalid-receiver diagnostics.
- Cache-key collision tests/documentation, bilingual guides and migration notes,
  dependency-free observability recipes, and ten-path runtime benchmarks.

During the final gate, existing retry regression tests exposed cancellation
inside shouldRetry being replaced by a business/decision error or producing an
exhaustion event. The failure was observed before the production fix. Retry now
checks cancellation after either callback outcome. The test's internal context
invocation also now explicitly preserves its readonly argument tuple.

## Public API and compatibility review

The saved 2.1 snapshot directories exist but contain no files in this session.
Consequently an exact 2.1-to-2.2 size, declaration or benchmark comparison cannot
be reproduced. V2.1-BASELINE.md is a historical report, not a restored binary
baseline. No measurements below are labeled as comparisons with 2.1.

Instead, source commit `91f1142` (2.0.0) was recovered using git archive and built
with the current installed toolchain. The committed api-size-comparison.json
covers all 96 runtime entrypoints. Across 48 ESM and 48 CJS entrypoints, the only
runtime export additions are semaphore and SemaphoreQueueFullError in
`/operators`; there are no removals. Export conditions and runtime dependencies
remain unchanged. There are still zero runtime dependencies.

declaration-deltas.json resolves exported aliases and records changed exported
declaration text across 48 ESM declaration entrypoints against that same 2.0
source baseline. Reviewed additions are SemaphoreOptions, SemaphoreKeyContext
and InvocationInfo, optional resilience/cache fields, generic breaker callback
information and WithHandle option restrictions. The inherited 2.1 event/state
checks are also visible against 2.0. CommandHistory and several option changes
include documentation-only declaration changes. Installed .cts consumers
independently verify CJS declaration resolution.

The RC is a minor-version candidate for the additive 2.2 capabilities. It also
includes unreleased 2.1 fixes and stricter declarations: consumers relying on
previously unchecked events/states may need source changes. Stable-release
compatibility requires consumer review; this RC does not promise every invalid
2.0 program will still compile. Default cache identity/scope/TTL, PolicyEvent
variants, PolicyErrorCode and cancellation isolation are preserved.

overhead relative to 2.0. Sample percentiles describe sample means, not
individual call latency. Timings remain informational rather than a CI gate.

## Architecture, exclusions and remaining release work

PermitQueue stays internal and shared by queueing operators. Decorators adapt
operators; receiver state uses WeakMap, not registries. InvocationInfo contains
readonly data rather than mutable execution controls. Vendor recipes inject
callbacks and do not add SDK dependencies.

POST-2.1-RFCS.md completes the design-only scope. Refcount cancellation,
functional rate limiting, asynchronous StateMachine versioning, distributed
store-backed policies/locks, vendor SDKs and global testing/reset registries
remain explicitly deferred. No public proposal is implemented merely by
appearing in that document. The existing StateMachine completion race and
wall-clock limitations remain documented debt; unbounded cache defaults remain
for compatibility, with explicit cachedFor capacity now available.

The authorized local RC preparation is complete. External release work remains:
run the Ubuntu Node 20/22 CI matrix after pushing, obtain consumer feedback,
review original audit attachments if supplied, and make the stable-release
decision. No package publish, Git tag, deployment or push is part of this local
closure. Recovering the original 2.1 snapshot is necessary only if an exact
intermediate-baseline comparison is required later.
